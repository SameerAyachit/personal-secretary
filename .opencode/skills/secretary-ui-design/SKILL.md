# Secretary UI design rules (implements plan §12; the plan wins on any conflict)

Scope lock: build only the screens, states and controls named in plan §12. No extra views, animations, or settings.

## 1. Tokens (one file: `src/secretary/ui/theme/tokens.py`; QSS is GENERATED from tokens, never hand-edited)
- Spacing: 4 / 8 / 12 / 16 / 24 only. Radii: 6 (controls), 10 (cards), 999 (chips). Window margins 16, card padding 12-16, row height >= 36 px.
- Type (Segoe UI Variable, fallback Segoe UI, then sans-serif): title 20 semibold, section 15 semibold, body 13 regular, caption 11 regular. Never below 11 pt-equivalent.
- Semantic colors only (no raw hex in widgets): `bg`, `surface`, `surface_alt`, `border`, `text`, `text_muted`, `accent`, `accent_text`, `danger`, `success`, `warning`, `focus`.
- Starting palette (adjust only to hit contrast):
  - Light: bg #F5F6F8, surface #FFFFFF, surface_alt #EEF0F3, border #D9DDE3, text #1B1F24, text_muted #5B6573, accent #2F6FED, accent_text #FFFFFF, danger #C62828, success #1E7A3C, warning #9A6700, focus #2F6FED.
  - Dark: bg #14171B, surface #1C2026, surface_alt #242A31, border #323A44, text #E8ECF1, text_muted #9AA6B5, accent #6EA2FF, accent_text #0B1220, danger #FF6B6B, success #4CC26F, warning #E3B341, focus #6EA2FF.
- Theme: follow the Windows setting, manual override in Settings (system|light|dark, config `app.theme`). Look up the current Qt API for color scheme detection before using it; do not guess.

## 2. Layout
- One main window: left rail (fixed 200 px, icon + label, selected item = accent bar + surface_alt) with Today, Chat, Tasks, Calendar, Inbox, Approvals, Settings; content area on the right in a `QStackedWidget`. Badge counts on Inbox and Approvals (number + shape, not color alone).
- Cards = `surface` background, 1 px `border`, radius 10. Lists use consistent row template: leading status icon, title (body), meta (caption, text_muted), trailing actions.
- Use layouts only (QVBoxLayout/QHBoxLayout/QGridLayout). No fixed pixel geometry except the rail width and minimum sizes. Minimum window 900x600. Content must not clip at 125% and 150% scaling.
- Chat: user bubbles right (accent), assistant bubbles left (surface_alt), tool-call chips (pill radius, caption), Undo as a text button in the bubble, status line "waiting ~Ns for the rate limit", Stop button replaces Send while a turn runs.
- Popup reminder card: frameless, always on top, bottom-right of the primary screen, title, body, Snooze / Done buttons, no focus steal.

## 3. States (REQUIRED for every view, each with its own small widget)
empty, loading, error (message + action button from plan §12.6), offline, rate-limited. A view without all five does not pass review. Empty states use one line of text plus one primary action; Chat empty state shows 4 example prompts.

## 4. Accessibility (plan §12.4; test them)
- Full keyboard navigation: logical tab order, Enter/Space activate, Esc closes dialogs and quick capture, Ctrl+1..7 switch views.
- Visible focus ring on every focusable control (2 px `focus`, offset 1).
- `setAccessibleName` on every icon-only button and every input.
- Contrast >= 4.5:1 for text, >= 3:1 for icons/borders. Provide `tests/ui/test_contrast.py` computing ratios from tokens for BOTH themes; it must pass.
- State is never color alone: pair with icon or text (e.g. "Overdue" label + icon).

## 5. Icons
One consistent set, bundled as SVG in Qt resources (stroke 1.75, 24x24 grid, `currentColor`, tinted per theme at load). No network downloads. Hand-write simple SVGs for the ~20 needed icons (today, chat, tasks, calendar, inbox, approvals, settings, add, check, snooze, undo, stop, send, search, warning, error, offline, clock, trash, more). App `.ico` 16-256 and two tray variants (normal, unread badge) are generated by a small script in `packaging/`.

## 6. Qt gotchas (look up current docs before relying on any of these)
- QSS is not CSS: no flex/grid, limited selectors. Style via `objectName` and dynamic properties (`setProperty("variant","danger")` then re-polish with `style().unpolish/polish`).
- Generate QSS from tokens in one function; apply at app level, re-apply on theme change.
- Never mutate widgets off the main thread (plan §3.1). Long lists: use model/view (`QAbstractListModel` + delegate), not hundreds of widgets.
- Set `QT_ENABLE_HIGHDPI_SCALING`/rounding policy per plan §12.1 before creating `QApplication`.

## 7. Screenshot review loop (run for every UI task; plan §17 tests/ui)
1. Add or update `tests/ui/test_screenshots.py`: for each view in light AND dark, offscreen (`QT_QPA_PLATFORM=offscreen`), at 100% and 150% scale, call `widget.grab().save("docs/screenshots/<view>_<theme>_<scale>.png")` for each state.
2. If your model can view images: open the PNGs and check against this checklist. If it cannot: run the programmatic checks instead (no widget whose `sizeHint` exceeds its size, no empty text on labels, tab-order test, contrast test) and add the PNG paths to `docs/human_todo.md` for the human to eyeball.
3. Checklist: spacing only from the scale; one accent; aligned left edges; no clipped or overlapping text; every state present; focus ring visible; dark theme not just inverted (surfaces differ by step); nothing decorative that the plan did not ask for.
4. Fix, re-run, record in `docs/progress.md`. Max 3 visual-fix cycles per view, then log in `docs/blockers.md` and move on.

## 8. Definition of "UI task done"
Tokens used (grep finds no raw hex outside tokens.py), all five states, a11y tests green, screenshots produced for both themes, layering respected (ui never imports store or llm), `ruff`, `pytest -q`, `lint-imports` green.
