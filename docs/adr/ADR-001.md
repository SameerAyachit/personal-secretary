# ADR-001: Record decisions D1-D15 from plan §2

Date / Status: 2026-11-07 / accepted

Context: The plan's Section 2 defines fifteen standing decisions (D1-D15) that govern the build. They must be recorded as ADRs so they are visible and revisable, per plan §2 and EXECUTION_PROTOCOL §0.

Decision: Adopt all fifteen decisions exactly as stated in the plan:

- D1: Native desktop app, PySide6 (Qt for Python), Qt Widgets plus a QSS theme. Revisit if Phase 0 UI spike shows Widgets cannot reach acceptable polish; then try QML for the Today view only.
- D2: No HTTP server, no auth token handshake. UI and agent share a process.
- D3: UI talks to the core through a `Controller` facade (signals and slots), never to the DB or LLM directly.
- D4: CLI is optional; in v1 it is a thin client over a named pipe (or cut).
- D5: LLM behind a provider interface (OpenAI-compatible), config-driven.
- D6: Eval suite is permanent and runs in CI against the FakeLLM contract plus on demand against live models.
- D7: Dates and recurrence resolved by code (`dateparser` plus a small rule parser); LLM passes `when_text`.
- D8: SQLite (WAL) + FTS5, single writer, migrations via a runner with a `schema_migrations` table.
- D9: Secrets in Windows Credential Manager via `keyring`; fall back to DPAPI-encrypted file if packaged app cannot reach the backend.
- D10: Notifications: inbox first, toast second, popup card third.
- D11: Start at login via HKCU Run key written by the installer, `--minimized` flag; Task Scheduler snippet kept for dev.
- D12: PyInstaller one-folder build + Inno Setup installer, built in CI.
- D13: Google integration optional and bring-your-own-credentials for public releases.
- D14: Untrusted-content quarantine: when processing email, web, or calendar text, the LLM gets no write tools.
- D15: Package an installer in Phase 0, not Phase 5.

Alternatives: Each decision's alternative is noted in its "Revisit when" column (above). None are adopted at this time.

Consequences: Good — single-process native app, small attack surface, clear layering, injection defence by quarantine, packaging early. Bad — Windows-only, PyInstaller AV risk, Google BYO friction for public releases. Follow-up: these are re-confirmed or changed at each phase exit checklist.
