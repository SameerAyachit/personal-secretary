# ADR-008: A daily, anonymous GitHub release check

Date / Status: 2026-11-15 / accepted

Context: Plan 18.3 says v1 updates are manual from GitHub Releases, but the app should tell the user when a newer release exists. That is the app's first outbound call that is neither the LLM, Google, nor a web search the user asked for, so it needs an explicit decision and disclosure.

Decision: once a day the scheduler thread makes one unauthenticated `GET https://api.github.com/repos/<repo>/releases/latest` (`integrations/updates.py`). The request carries no token, no cookies, no app version and a generic User-Agent (`secretary-update-check`). Only the release tag and a `https://github.com/` link are kept (in the `settings` table); a link pointing anywhere else is ignored, and drafts, pre-releases and malformed answers are ignored. A failed check retries after an hour, a successful one after 24 hours. The main window shows an "Update available" banner (Open release page / Dismiss; a dismissed release stays hidden until a newer one appears). Nothing is downloaded or installed. `[updates] check = false` in `config.toml`, or the Settings > General switch, turns it off and no request is then made. The repository is `[updates] repo`, default `SameerAyachit/personal-secretary`.

Consequences: GitHub (and anyone on the network path) sees the user's IP address once a day, like any web request; this is stated in `PRIVACY.md`. A private or release-less repository answers 404, which is treated as "no update". Tests use `httpx.MockTransport` only; no test or tool of this project calls GitHub. To revisit: signature or checksum verification if silent auto-update is ever added (out of scope for v1).
