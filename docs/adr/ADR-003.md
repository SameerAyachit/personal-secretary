# ADR-003: Google Calendar write-back for events created in chat

Date / Status: 2026-11-14 / accepted

Context: Plan §13.3 and Phase 3 call for class-B calendar writes (own events, no attendees), but only read sync was built, so events created in chat were stored in SQLite and never reached Google Calendar. §22.3 lists "Calendar writes → keep read-only sync" only as a scope-cut fallback.

Decision: `event_create` writes the local row with `sync_state='pending'` and a client-chosen Google event id (migration 007). The scheduler tick pushes pending events with `events.insert` before each read sync. Create only: no update/delete tools in v1; events with attendees remain class C and are out of scope.

Rationale: The tool stays pure (no client plumbing or globals) and works offline. Reusing the same id on every attempt makes retries idempotent (HTTP 409 means "already created"). Network/5xx/429 errors stay pending; other 4xx errors mark the event `failed` with the reason shown in the Settings sync chip. The tool result reports `google: queued | not_connected` so the model never claims a sync that has not happened.

Consequences: Events appear in Google within one scheduler tick (30 s). Read sync is now throttled to `google.sync_minutes` instead of every tick. Connecting Google mid-session hands clients to the running scheduler, so no restart is needed.
