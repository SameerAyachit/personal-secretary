# ADR-005: Background research jobs and real Gmail sending

Date / Status: 2026-11-15 / accepted (explicit user decisions)

Context: Testing the running app showed three problems. (1) Research inside a chat turn found no sources, blocked the shared worker loop and bypassed the rate limiter. (2) An approved email was only marked "executed" ("sending is not enabled yet"), drafts were invisible, and the approval summary named the sender instead of the recipient. (3) Inbox items disappeared after Ack/Snooze/Done.

Decision:
- Research runs as a background job. The `research_brief` tool creates a `research_briefs` row (migration 008), starts the pipeline with `asyncio.create_task` on the worker loop and returns "started" immediately. The job records the brief or the failure, and adds an Inbox item when finished. The Research tab uses the same job and lists recent briefs. Research LLM calls go through `MeteredClient` (same limiter as chat, background priority, so interactive turns win), 429 responses are retried with `Retry-After` (capped), and blocking calls (`ddgs`, page fetch) run in threads.
- Approve sends the email. `GmailClient.send_message` posts a base64url RFC 2822 message to `users/me/messages/send` (verified against the Gmail API reference; `gmail.compose` already allows it). Class C rules are unchanged: nothing is sent without an approval whose summary is built in code from the draft's real recipients and subject; the draft is re-fetched and compared with the approved snapshot; the first `waiting -> approved` transition wins, so a double click cannot send twice; the network call runs off the GUI thread; the outcome (`executed` or `failed` with a reason, "Reconnect Google" on HTTP 401/403) is stored and shown in the Inbox. A sent draft becomes `source='sent'`, so its recipients count as known addresses.
- Drafts live in Approvals > Drafts (Request send / Discard). The system prompt and tool descriptions say there is no outbox.
- Inbox keeps every item and exposes filters plus Reopen, instead of hiding anything that is not New.

Consequences: (1) The app can now send real email from the user's Gmail account once Google is connected with the compose scope; users who connected before the scope was added must Reconnect Google. (2) A crash between approval and the Gmail response leaves an action in `approved` (it was not retried, to avoid a duplicate send); the user can check Gmail's Sent folder. (3) Plan §3.5 said sending was human-gated; this records the deviation.
