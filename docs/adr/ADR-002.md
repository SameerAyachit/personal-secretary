# ADR-002: UI toolkit — Qt Widgets (not QML) for the Today view

Date / Status: 2026-11-07 / accepted

Context: Plan §21 P0-08 asks for a UI toolkit ADR (Widgets vs QML for Today) with a one-screen prototype. Plan §2 D1 and §4.1 already specify "Native desktop app, PySide6 (Qt for Python), Qt Widgets plus a QSS theme". §12 specifies a left-rail main window, QSS-generated tokens, light/dark themes, and model/view for lists — all Widgets-native.

Decision: Use Qt Widgets + QSS for all screens (Today, Chat, Tasks, Calendar, Inbox, Approvals, Settings). Do not use QML.

Rationale: Widgets match the plan's D1 and §12 specification, are simplest for flash-tier models to write correctly, integrate directly with QSystemTrayIcon / native toasts / global hotkey, and avoid maintaining two UI toolkits. The QSS theme is generated from a single tokens file (`src/secretary/ui/theme/tokens.py`) per the secretary-ui-design skill.

Alternatives considered:
- QML for Today only: rejected — adds a second UI toolkit, contradicts D1, and the plan's screen specs (model/view lists, cards, tool-call chips) are Widgets-natural.

Consequences: One UI toolkit to maintain; QSS theming must be generated from tokens (never hand-edited raw hex in widgets); high-DPI scaling handled via QT_ENABLE_HIGHDPI_SCALING. The P0-04 shell (main window, tray, popup, hotkey) serves as the one-screen prototype confirming Widgets work in dev.

Revisit when: Phase 0 UI spike shows Widgets cannot reach acceptable polish; then try QML for the Today view only.
